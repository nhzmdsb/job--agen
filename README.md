# 个人求职工作台 V0

2026-10-12：在原项目上新增可操作工作台，保留 Python、SQLite、记录 envelope、版本检查、完整历史、CLI 和 MCP。此版本取代旧计划中的「禁止 GUI」「采集优先」「生命周期以后实现」。后台自动化整理信息，用户决定策略、简历和最终申请；程序不自动投递。

## 打开和使用

Windows 双击 `start-workbench.cmd`，浏览器打开 http://127.0.0.1:18765 。首次启动安装 Flask 和 Waitress；之后直接启动。关闭启动窗口会停止本地服务。仅监听本机。

主页面看岗位卡片，右侧切换机会池、准备投递、已投递、面试中、已结束和回收站。点卡片默认阅读中文摘要、完整中文 JD、判断理由和证据，可展开完整原文；需要修改来源事实时再点“更正岗位资料”。逐项依据以卡片呈现，按钮展开原文与档案依据；待确认事项单独展示。备注自动保存并显示状态。四色由资格证据和兴趣决定，颜色与进度独立，未知资格或缺 JD 为灰色；人工调整必须填写原因。没有匹配分数。招聘年份、面向届别和允许申请年份分别记录，不能把「2026 招聘」推断为「2026 届可申请」。

在详情的“移动到”选择进度后立即保存，无需再保存表单。不考虑的岗位可填写原因并“移入回收站”，保留历史和去重，之后仍可恢复到机会池。删除单个岗位不会自动改变求职偏好；希望减少同类机会时，另在“我的档案”更新明确不能接受的职责，Work 按职责原文重新判断。

岗位详情可以上传真实 PDF/DOCX、下载原文件、选择四种准备任务并生成 Prompt。复制后打开 ChatGPT 粘贴；附件需要在新会话另行上传，Prompt 不表示 ChatGPT 已读取附件。超出公司同批次名额时必须明确确认并填写原因。回收站保留去重标识，已结束保留历史。


## 档案与 Work 判断

“我的档案”是日常维护入口，分开显示已确认资料、待确认事项、经历、偏好和来源。修改后自动进入现有私有同步流程。重新读取 Notion 的按钮生成处理 Prompt；获授权 Work 读取后保存差异建议，用户在工作台确认才更新档案。没有 Notion 双向同步，也不自动执行按钮生成的任务。

工作台区分 Work 判断、程序辅助检查、人工调整和待重新判断。强制条件明确不符或触及明确不能接受条件的机会退出主机会池，入口位于右侧默认折叠的“更多记录 → 已收起”；可在详情“放回机会池”，投递进度不变。未知证据保持灰色，优先条件不符保留黄色。绿色还需要用户确认兴趣。档案或岗位事实变化会让旧判断失效，停止自动折叠和着色；备注修改不会使资格判断失效。

英文及中英混合岗位保存中文标题、简短摘要和完整中文 JD，覆盖原文各节；详情保留原始标题与完整原文。原文变化后提示待更新，只有标题摘要的旧记录提示待补全文。卡片展示主要理由，详情用证据卡片和展开按钮呈现逐项依据，待确认问题单独呈现。“标记来源问题”只保存核验请求，不宣称刷新成功。页面显示待处理数量，可复制处理 Prompt 并打开 ChatGPT。

截至 2026-10-12，38 条非回收站岗位拥有有效 Work 判断，32 条拥有完整中文翻译；机会池 12 条、已收起 26 条、回收站 1 条。没有为凑颜色编造资格或兴趣。Notion 实际差异仍是待确认建议，没有自动接受；完整中文 JD 新任务规则的下一次定时执行尚未验证。

## 数据与协作

个人工作副本、附件、设置、备份位于 `%LOCALAPPDATA%\JobAgent`；可用 `JOB_AGENT_HOME` 调整。原 `data/workspace.sqlite3` 被保留，默认数据库首次迁移前用 SQLite 备份。公开仓库只存代码、文档和虚构测试数据。

私有 GitHub 仓库优先作为共享权威源。本次已建立并验证 `nhzmdsb/job--agen-data` 私有属性与真实读写。`settings.json` 只记录 `{"repository":"nhzmdsb/job--agen-data"}`；凭据由现有 Git Credential Manager 提供，不写入配置或浏览器。连接任何仓库前检查私有属性。云端不可用时本地照常保存并显示待同步。

每次修改同时保存版本、历史和待同步事项。后台在写入后、启动时同步；页面刷新发起检查，每六小时补充维护。不同记录可合并，同一记录并发修改保留双方，在页面选择合并，双方完整历史归档到私有仓库。同步 JSON 与按 SHA-256 保存的原文件，不同步 SQLite 文件。运行依赖电脑开机且本地服务运行；定时 Work 任务另见交接记录。

读取后保留未知字段，版本化写入，不能强制覆盖。[共享协作协议](docs/COLLABORATION.md) 包含 HTTP、CLI、MCP 和私有仓库写入方式。

## 开发与验证

```powershell
py -3 -m venv .venv
.venv\Scripts\python.exe -m pip install -e ".[mcp]"
.venv\Scripts\python.exe -m unittest discover -s tests -v
.venv\Scripts\python.exe -m job_agent.web --no-browser
```

CLI：`python -m job_agent.cli init/list/get/put/history/export/import/sync/review-pending`，JSON 从标准输入读取。`put` 更新必须提供 `--expected-version`，并提交保留未知字段的完整 data。MCP：`python -m job_agent.mcp_server`，仍为 stdio，复用同一存储。历史导入先验证完整快照再原子恢复，保留原 ID、版本和历史。

岗位发现：`python -m job_agent.discover --batch 4` 先枚举 Louis Dreyfus Company 中国岗位、中兴新云校招目录及 IFF 的 China 搜索分页，再按每来源最多四条读取尚未处理的详情。保存新链接、完整 JD、访问时间、原始响应、资格证据及下一批进度。失败保留灰色入口，24 小时后重试；垃圾桶不重新推荐。目录仍会重新检查新发布内容，不反复获取已有完整 JD。当前只覆盖这三个官方目录，不宣称独立搜索全网或发现任意新企业。

`python -m job_agent.collect` 仍用于刷新已知 Canonical URL；`python -m job_agent.cli sync` 负责私有数据同步。已分开配置每六小时的「求职工作台六小时同步维护」和「求职工作台六小时岗位发现」任务，本机需开机且 Codex 应用运行及网络可用。本次收到实际发现任务触发并完成处理；更新后的完整中文 JD 规则下一次定时执行尚未验证。仅报告实质变化、失败或需要处理的事项。
