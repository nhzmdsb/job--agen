# AI 的公司与岗位扫描约定

先从需求决定检索范围，业务判断由 AI 完成，程序只负责读写与保存。

## 公司优先顺序

1. 先从招聘汇总表找近期（2026年8月起，优先最近更新）且标记2026届可投的公司；标签只作线索。原招聘入口需核验，不能认为标签准确。
2. 保留2027届线索与2026可投线索的并集；在已选公司的当前目录内寻找接受2026毕业生的岗位或明确毕业窗口。旧Q&A不覆盖当前JD。
3. 每家公司先枚举完整当前目录，记录总数、分页和唯一岗位标识；再按职责与资格选择阅读深度。不能以5岗样本推断46岗均相同。

## 岗位阅读顺序

专业不限或明确包括农学、植物科学、种子、植保等相关专业的优先。营销、销售、产品、运营等方向重点检查；工程师不能仅凭名称排除，需先看学历、专业与实际职责。硬性学历、在校身份、毕业届次及毕业窗口单独判断。

专业表述保持原意：

| 表述 | 记录方法 | AI 的投入判断 |
| --- | --- | --- |
| 专业不限 | unrestricted | 优先继续看其他要求 |
| 某专业优先 | preferred | 不改写为硬限制；结合技术门槛、业务背景和候选人可证明经历，降低或提高投入优先级 |
| 某专业、相关专业，无“优先” | required_or_unspecified | 保留原句，判断是否真实资格门槛；不补出“只招” |
| 仅限/须为/限定某专业 | required | 按明确硬条件判断，不因技能相关就自动放宽 |
| 未写专业 | unknown | 不等于专业不限 |

如果偏好专业与职责高度绑定，即使原文只写“优先”，可认为竞争劣势明显，降低优先级，但不能把推断当招聘方硬性排除。任何个人匹配结论都保留理由与证据。

## 完整覆盖与未知项

目录项至少记录性质、届次、学历、专业表述、地点、URL和读取状态。记录已读、未读和具体失败；仅在全部目录项有结果时称全量扫描。全量扫描可以发现不匹配岗位，不能只保存适配项后丢失覆盖依据。实习与全职分开，在校身份不能因为有2026标签被忽略。

来源日期、届次和投递入口相互核验。微信工具策略受限、普通登录要求、空白页和网站反自动化分别记录。AI 的筛选理由与分组属于可调整分析，不加入程序化评分、自动合并或去重逻辑。

## 飞书筛选验证

本轮验证「招聘届次 → 包含 → 2026届」在匿名只读视图生效，结果从15490减少为9636；其中可见2027+2026多标签记录。该条件只用于挑选本轮2026可投公司，不代表覆盖2026、2025/2026、不限届等其他标签。新一轮完整搜索仍要扩展标签并集，并结合近期日期，不以9636作为有效在招公司数。
