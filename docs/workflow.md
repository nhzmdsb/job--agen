打开工作台 → 看机会卡片和原始来源 → 在详情补充证据、兴趣和备注 → 按需要准备投递/面试 → 生成 Prompt，复制并打开 ChatGPT → 用户自行申请，记录实际进度与结果。

# 搜索池 V0

## 已确定的边界

用户或 AI 提供线索，AI 使用宿主的工具读网页、表格或附件，将原始信息保存，再选择性补全岗位，作出资格与偏好判断。程序提供通用读写能力，不替 AI 做这些判断。

## 下一步一起确认信息源

首先接入一个用户提供的真实信息源。确认入口、访问方式、需检查的范围以及如何判断是否读完。用一小批真实内容验证：能读到哪些信息、还需去哪里补全、哪些岗位值得保留、重复内容如何关联、进度如何续跑。

AI 的一次运行：读取 profiles 与 sources，创建 runs 记录；读取指定范围；保存 leads；查看已有 jobs 并自行决定新增、关联或更新；写下证据、未知条件和下一步；保存处理进度；汇报新增岗位、变化和阻塞。

停止、登录失败或网络失败时保留已保存内容及 run 进度。只有完成核验的内容才更新核验时间；失败不意味着岗位关闭。

## 当前验收

AI 可以创建来源，保存原始线索和岗位，分页读取，修改记录，发现并发覆盖，查看历史，恢复旧内容，导出记录。所有来源初始为空，不会主动采集。

## 后续再决定

真实来源适配、Notion 共享存储、附件管理、调度和求职后续状态。需求明确后复用适当开源项目；本轮不做这些功能的空实现。
